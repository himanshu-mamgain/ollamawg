Your Ollama on your laptop and phone. Not on the internet.

ollamawg puts an encrypted WireGuard tunnel in front of Ollama. It adds per-device access control, a dashboard that shows who is connected and what they run, and a ChatGPT-style chat page for phones. Ollama itself never leaves 127.0.0.1.

irm https://himanshu-mamgain.github.io/ollamawg/install.ps1 | iex
curl -fsSL https://himanshu-mamgain.github.io/ollamawg/install.sh | sh
npm install -g @ollamawg/cli
go install github.com/himanshu-mamgain/ollamawg/cmd/ollamawg@latest

No admin rights needed. Or download a binary from GitHub Releases. Not independently audited yet; see the security model.

The problem

Ollama has no authentication. If you set OLLAMA_HOST=0.0.0.0 and forward port 11434 so you can use your GPU box from elsewhere, anyone who finds the port can run your models, pull new ones and delete the ones you have. Scanners find these ports within hours.

The fix

Keep Ollama on loopback and open only a WireGuard port. WireGuard ignores every packet that isn't from a key you registered, so to the internet it looks closed. Inside the tunnel, ollamawg decides what each device may do and records what it did.

How it works

Every request passes three checks before it reaches Ollama.

Laptopollamawg connect: apps use 127.0.0.1:11434
PhoneWireGuard app, browser at 10.77.0.1:11434/chat
UDP 51820
encrypted
1FirewallIP and CIDR rules drop packets before WireGuard sees them. Every source is counted.
2WireGuardOnly registered keys complete a handshake. Each device gets one tunnel IP.
3Policy proxyRole, model allowlist and rate limit per device. Every request is logged with token counts.
Ollamaon 127.0.0.1:11434, unreachable from outside

WireGuard runs in user space (wireguard-go on gVisor's network stack), so the server needs no root, no kernel module and no TUN device. Keys are standard WireGuard keys, which is why the official phone apps work unchanged.

What you get

Per-device policy

Roles (user, readonly, admin or your own path rules), model allowlists like llama3.2,qwen3:*, and requests-per-minute limits.

One-click blocking

Block a device and its session is cut instantly. Block an IP or a whole network before it ever reaches WireGuard, or switch to default-deny.

See everything

Who is connected and from where, requests and tokens per device and model, policy denials, and every source knocking on the port. Prometheus metrics included.

Phones by QR code

Scan a QR code in the official WireGuard app. Only the server's tunnel address is routed, so the phone's other traffic is untouched.

Built-in chat page

A mobile-friendly chat at /chat: streaming replies, Markdown and code blocks, a model picker, history kept on the device, and Add to Home Screen.

Dashboard 2FA

Optionally protect the dashboard with Google Authenticator, Authy or 1Password. Choose your own username and password; it's stored as a bcrypt hash.

Hot reload

Adding, blocking or editing devices applies within 2 seconds without dropping anyone's session, whether from the CLI, the dashboard or a hand edit.

Works with your tools

The ollama CLI, Open WebUI, LangChain, Continue and any OpenAI-compatible client work unchanged through the tunnel. It's also a Go library.

Install

Pick one. All of them give you the same ollamawg command.

Windows

In PowerShell. Installs to %LOCALAPPDATA%\Programs\ollamawg and adds it to your PATH.

irm https://himanshu-mamgain.github.io/ollamawg/install.ps1 | iex

macOS, Linux, FreeBSD

Installs to /usr/local/bin if writable, otherwise ~/.local/bin. Never uses sudo.

curl -fsSL https://himanshu-mamgain.github.io/ollamawg/install.sh | sh

npm

Prebuilt binaries for each platform, no install scripts. Or run it once with npx @ollamawg/cli.

npm install -g @ollamawg/cli

Go

Builds from source. Needs Go 1.24 or newer.

go install github.com/himanshu-mamgain/ollamawg/cmd/ollamawg@latest

The install scripts download from GitHub Releases and check each binary against the release's SHA256SUMS. Read them first if you like: install.sh, install.ps1. To pin a version, set OLLAMAWG_VERSION=0.4.0. A Dockerfile is included too.

Quickstart

You need Ollama on the server with at least one model (ollama pull llama3.2).

  1. Create the server config

    ollamawg init --endpoint your-public-ip-or-dns:51820

    This writes server.yaml with fresh keys and prints the dashboard login. Forward UDP port 51820 on your router or cloud firewall to this machine.

  2. Start the server

    ollamawg serve

    Open the dashboard at http://127.0.0.1:8088 on the server, or over SSH with ssh -L 8088:127.0.0.1:8088 server.

  3. Add a laptop

    ollamawg add-peer --name laptop        # on the server: writes laptop.yaml
ollamawg connect --config laptop.yaml  # on the laptop
curl http://127.0.0.1:11434/api/tags   # any Ollama client now works

  4. Add a phone

    ollamawg add-peer --name phone --qr

    Scan the QR code in the WireGuard app, turn the tunnel on, and open http://10.77.0.1:11434/chat. Details below.

Phones and the chat page

Phones don't need any ollamawg software. The server is a standard WireGuard peer, so the official app does the job.

  1. Run ollamawg add-peer --name phone --qr, or use Add device → Phone in the dashboard.
  2. In the WireGuard app (iOS, Android), tap + → Create from QR code, scan, and give the tunnel a name such as ollamawg.
  3. Turn the tunnel on and open http://10.77.0.1:11434/chat. Use Share → Add to Home Screen to open it like an app.

The chat page has no separate login: the phone's WireGuard key identifies it, and its role, model allowlist and rate limit apply. Chats stay in the phone's browser. Ollama apps such as Enchanted or Reins also work: point them at http://10.77.0.1:11434.

Missed the QR code or lost a config? The server never stores device private keys, so a config can't be shown twice. Run ollamawg reissue --name phone --qr, or press New config on the device in the dashboard. The device keeps its name, address and policy, and its old config stops working.

Dashboard login

Username and password

init creates the user admin with a random password. To choose your own, run the command below. A password you choose is stored only as a bcrypt hash.

ollamawg passwd                   # asks twice, hidden as you type
ollamawg passwd --user yourname   # also change the username

Two-factor login

Add a 6-digit code from an authenticator app. You can also use the 2FA button in the dashboard. Scripts and Prometheus then use an API token.

ollamawg 2fa enable    # scan the QR code, confirm a code
ollamawg 2fa disable   # the way back in if you lose your phone

Security model

Status: not independently audited. Treat ollamawg as an evolving security tool, not an independently verified security product. The cryptography is wireguard-go and gVisor, which are widely deployed; ollamawg's own policy, proxy and dashboard code is small and covered by end-to-end tests, but no outside party has reviewed it yet. Read the security model before relying on it, and report problems.
  • Ollama stays on loopback. The server warns at startup if Ollama is also reachable on another address.
  • Keys, not passwords, admit devices. Unregistered keys can't complete a handshake, and the port stays silent to them.
  • Blocking is immediate. A blocked device's session keys are discarded; blocked IPs are dropped before decryption.
  • Device private keys are never stored on the server. A leaked server.yaml can't impersonate your devices.
  • The dashboard is privileged and local. It listens on loopback, refuses DNS-rebinding hosts, needs a CSRF header for changes, and sends a strict CSP.
  • Prompts are never logged. The access log records metadata only: device, IP, path, model, status, timing and token counts.
  • The chat page is served inside the tunnel only, and Ollama's own origin checks still apply to everything else.
  • Tested end to end. Policy, blocking, 2FA, the chat page's origin handling and re-issuing are covered by tests that run a real tunnel.

Full details: Security model.

Requirements

  • Server: Linux, macOS, Windows or FreeBSD, with Ollama on 127.0.0.1:11434 (its default).
  • Computers: any of the above, running ollamawg connect. No admin rights needed.
  • Phones: the official WireGuard app for iOS or Android.
  • Network: devices must reach one UDP port on the server, 51820 by default.
Behind CGNAT? Many home and mobile ISPs share one public IP between customers, and then no port can be forwarded to you. Your router's WAN address starts with 10. or 100.64–127. in that case. You can still use your LAN address as the endpoint for devices at home, ask your ISP for a public IP, or relay through a small VPS. How to check.

FAQ

Why not just use Tailscale?

Tailscale is great at connecting machines, and it works through CGNAT, which ollamawg doesn't. ollamawg is about controlling an Ollama server you share. You get per-device roles, model allowlists, rate limits, token accounting, a request log and a built-in chat page, all self-hosted with no account or coordination server.

Does it work with Open WebUI, LangChain, Continue…?

Yes. On a computer running ollamawg connect, everything that talks to Ollama on 127.0.0.1:11434 goes through the tunnel unchanged, including OpenAI-compatible clients pointed at http://127.0.0.1:11434/v1.

Do I need root or admin rights?

No, on the server or on computers. WireGuard runs in user space inside the ollamawg process. Phones use the WireGuard app, which asks once for VPN permission.

I missed the QR code. How do I get it again?

Run ollamawg reissue --name phone --qr, or press New config in the dashboard. The server never keeps device private keys, so it issues a fresh one; the old config stops working.

Is my chat history stored on the server?

No. The chat page keeps history in the device's browser. The server's access log records metadata such as model and token counts, never prompts or replies.

Can several people manage the dashboard?

The dashboard has one admin account. If several people need it, put a reverse proxy with SSO in front.

Has it been security audited?

Not yet. Treat ollamawg as an evolving security tool, not an independently verified security product. The cryptography is wireguard-go and gVisor, which are widely deployed, and ollamawg's own code is small and tested end to end. The security model lists what it protects and what it doesn't.

What does it cost?

Nothing. It's open source under the MIT license.
